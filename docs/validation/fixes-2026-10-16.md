## lig/kern 字符入口

反例为 `fixtures/bad-boundary-entry.tfm`：字符 65 的 lig_tag 指向第 0 条记录，记录四字节为 `[255, 250, 255, 255]`，lig/kern 表只有两项。首条记录声明右边界字符 250，但作为字符入口使用时还必须解析地址 `256*255+255=65535`。旧版本错误返回 ok；新增回归测试在修复前确实失败。TFtoPL 对同一文件报告字符入口过大并移除它。

修复后返回 INDEX_OUT_OF_RANGE，byte_offset=62、character_code=65、expected_min=0、expected_max=1、actual=65535。glyph 与 diff 不再接受此文件。字符入口的诊断保留字符上下文，通用控制记录检查避免再报告同一入口错误。

新增回归还覆盖纯右边界声明、声明兼入口、单记录左右边界、首末边界组合、双字节地址 256、skip=128 普通操作、skip>128 仅在字符入口重启一次，以及缺失字符不产生入口引用。不把普通控制停止解释为无限递归重启。

## Windows 安装状态

编译器检查识别实际 `moonc -v` 输出 `v0.10.15+943464bfa (2026-10-12)`，精确匹配完整版本；不接受旧构建或额外版本后缀。标准库从自身 `moon.mod` 读取完整版本，与 `moon-toolchain` 比较，不能仅凭文件存在复用。

更新标准库时先在安装目录内的独立暂存区解压并确认版本，再移动旧目录和新目录，清理不再适用的旧源码和构建缓存。错误版本或损坏 ZIP 在替换前停止，保留原标准库；新目录移动失败时尝试恢复旧目录。递归移动/清理前验证绝对路径属于预期安装或测试目录，拒绝路径中的符号链接或 junction。
