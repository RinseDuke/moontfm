# MoonTFM 首版设计

2026-10-15 实现更新：首版已按此范围落地，核心与 JSON 报告使用 MoonBit，CLI 选择 JS 后端与 Node.js 文件输入层。当前 API 和实际边界见 `API.md`，验证证据见 `VALIDATION.md`；下文保留最初设计依据。

项目交付目标是一个纯 MoonBit 文件解析与分析库，以及一个薄文件输入层的 CLI。首版支持经典 8 位 TeX TFM，围绕结构诊断和字符度量变化展开。

## 使用场景

字体文件体检：读取一个文件，解释设计字号、字符范围、表规模，并给出带字节位置的结构与引用诊断。

字体发布检查：比较两个版本，定位哪些字符新增、移除或改变了宽度、高度、深度、斜体修正，输出人类可读报告与机器可读 JSON。

库集成：其他 MoonBit 工具可以在内存中解析 Bytes、查询度量并生成差异，不需要启动外部解析进程。

## 首版范围

| 模块 | 必须完成的行为 | 完成证据 |
|---|---|---|
| reader | 有界读取二进制数据；统一处理截断与位置 | 不同字段截断的固定测试 |
| model | 原始度量、字符存在性、文件元数据 | 对可控样例逐字段核对 |
| parser | 完整读取经典 TFM 各表，不只解析文件头 | 完整样例与真实字体对照 |
| validate | 长度、表引用和结构关系检查；诊断含位置 | 对损坏文件给出预期错误 |
| metrics | 查询指定字符，处理不存在的字符 | 存在、缺失及边界字符测试 |
| diff | 根据解析后的字符度量比较，不按二进制偏移比较 | 度量等价但表布局不同的样例 |
| report | 文本与稳定 JSON schema；明确检查覆盖范围 | 报告快照与 CLI 流程测试 |
| CLI | inspect、validate、glyph、diff 四个命令 | 从样例输入到报告的可复现步骤 |

命令名称和 API 目前属于设计，实际调用形式在选定工具链后验证。

## 数据与诊断设计

度量使用原始定点整数保存。报告可附加十进制展示值；比较依赖原始值，不依赖浮点舍入。设计字号的变化与相对度量变化分开报告，避免把不同字号的物理尺寸误说成相同。

缺失字符与宽度恰好为零的已存在字符必须区分。字符编码按字体中的字节编码解释，首版不把它直接视为 Unicode，也不声称正确渲染文本。

诊断至少包含 code、severity、byte_offset、table、message，涉及字符时补充 character_code。索引类错误附带期望范围和实际索引。可恢复的结构问题允许汇总；无法安全读取的文件停止深入解析并返回结构化错误。

解析成功与校验通过是不同结果。CLI 必须说明其验证的是声明的结构与引用规则；完整 TeX 连字执行语义不属于首版承诺。报告应列出 coverage 和未覆盖项，不把返回空诊断解释为完全兼容。

## 关键检查

- 依据官方格式核对总长、各表长度、字符范围与零字符文件。
- 核对字符引用的宽度、高度、深度、斜体修正索引。
- 核对连字与字距表入口、跳转和引用，正确区分特殊控制记录；实现前逐条对应上游规则。
- 核对可扩展字符配方和 next-larger 引用，并制定循环诊断规则。
- 度量负数与边界值按规范分别处理，不能一概当作损坏。
- checksum 是字体兼容性标识，不是可从整个文件重新计算的通用内容校验和；首版展示或比较它，不实现伪造的 checksum 验证。
- JFM、OFM 等变体不在支持范围；发现无法确认支持的结构时明确拒绝或标记不支持，不能悄悄当作经典 TFM。
- 对恶意长度、异常索引和循环设置输入限制和有界检查。

## 度量差异边界

主报告比较字符是否存在、四类相对度量及设计字号。逻辑上相同的度量不会因表重排而被误报。其他表或元数据发生变化时，使用独立 change 标记，避免漏报后声称整个字体完全等价。

首版不解释所有连字程序为字符对规则，也不承诺从度量差异推断完整页面排版变化。相关变化会保留为明确的原始表变化或未深入分析提示。

## 工程安排

核心库独立于文件系统。优先选择经过验证的一个 CLI 后端；具体使用 native 还是 JS 由工具链与文件输入库的最小验证结果决定，不同时承担两个 CLI 后端。核心跨后端检查可在首版通过后补充。

原创测试样例与第三方真实字体分开保存。每个第三方样例记录来源、版本、许可证和获取方式；缺乏再分发许可时只提供下载说明，不提交文件。

TeXware 仅作为开发测试的参考工具，不是运行时依赖。交叉测试比较具体字段，不以参考工具进程退出码或打印的 PL 文本逐字一致作为唯一判定；参考工具可能警告并修正输入，需要保留这些诊断。

## 后续扩展

PL 序列化、完整连字语义、批量目录审计和更多字体格式可作为后续方向。首版不加入完整排版、字体图形渲染、TFM 写入、自动修复或复杂网页界面。
