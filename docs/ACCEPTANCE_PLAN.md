## 测试矩阵

| 类别 | 关键样例 | 要证明的行为 |
|---|---|---|
| 有效结构 | 最小字体、空字符范围、稀疏字符、各类表 | 模型和字段正确 |
| 读取边界 | 在不同字段或表内截断、长度不一致 | 有界读取和准确定位 |
| 表引用 | 度量索引越界、错误 lig/kern 入口、异常 next-larger | 引用规则按规范执行 |
| 数值 | 负数 kern、负数深度、设计字号边界 | 不把合法符号值一律拒绝 |
| 存在性 | 缺失字符、有效零宽字符 | 不混淆缺失与零度量 |
| 差异 | 一项度量变化、新增与移除字符、字号变化 | 报告能解释实际变化 |
| 等价 | 表重排但字符度量相同 | 不误报度量差异 |
| CLI | 有效输入、损坏输入、找不到文件、JSON 输出 | 输出与退出码可供脚本使用 |
| 交叉核验 | 有许可的真实字体及原创 PL 经 pltotf 生成的 TFM | 与 tftopl 的关键字段一致，差异有解释 |

优先覆盖这些有独立期望值的场景，再补随机截断和变异输入测试。测试数量本身不作为质量证明，不为达到某个行数或数量拆分无意义用例。

- 第三方文件及参考实现的来源和许可记录完整。
- AI 辅助生成的代码经过理解、验证和修正。
- 准备 Mooncakes 包发布；发布步骤涉及用户账号操作时由实际授权与访问能力决定。
- 根据赛事群和正式章程核对验收入口、附件要求与提交状态。

## 演示流程

先检查一个正常字体，再查询一个字符，随后检查一个被刻意破坏的样例，最后比较两个只改变一项度量的字体。四步展示读取、诊断和差异分析，不依赖网络或硬件。

演示输出必须来自实际命令运行；文档可以标示预期结果，但不能把预期结果当作已验证结果。
